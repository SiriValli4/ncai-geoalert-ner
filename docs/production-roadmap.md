# From local build to real-time product

A gap analysis of GeoAlert NER as of October 2026, based on the code in this repository. Every "Current Architecture" cell describes what the code actually does today; file paths point to the evidence.

**Bottom line:** the platform works locally end to end, with a verified PostGIS schema, a working API, a live map layer and mock SMS. The *real-time* parts don't exist yet: nothing ingests weather data, nothing scores risk on a schedule, and nothing connects a risk score to an alert. Two foundations also need replacing before any output can be trusted: both ML models were trained on **synthetic data**, and the API has **no authentication**.

## Suggested sequencing

Each phase delivers something usable on its own.

| Phase | Goal | Builds | Exit criterion |
|---|---|---|---|
| **0. Secure the base** | Safe to deploy anywhere | Auth on API + alerts service, CI with PostGIS tests, object storage for photos, staging environment | Staging reachable only by authenticated users; CI green on every PR |
| **1. Real data in** | Stop using sample data | Worker + scheduler, one rainfall source end to end (e.g. IMERG), `stations`, partitioned readings, QC, freshness metrics; map heatmap fed live | Rainfall layer updates automatically; stale data visibly flagged |
| **2. Real model** | Trustworthy scores | GSI inventory + historical rainfall training set, real terrain rasters, antecedent features, evaluation report, model registry | Documented recall on held-out real events, accepted by domain experts |
| **3. Automated risk** | Scores without a human clicking | Batch scoring after each ingest, `risk_assessments` history, push updates to the map, all layers live | Map reflects new data within minutes, with no manual refresh |
| **4. Alerts that reach people** | Operator-approved SMS | Trigger engine, approval UI, DLT registration, recipients + consent, queued dispatch, delivery tracking | End-to-end drill: simulated HIGH → approved → delivered to test recipients with full audit trail |
| **5. Scale & redundancy** | Population-scale reach | Throughput tuning, SACHET/cell broadcast evaluation, HA database, on-call | Load test at district-population scale; failover tested |

**Dependency to note:** phase 4 must not ship before phase 2. Automatically texting the public on the strength of a model trained on synthetic data would cause harm, through false alarms that erode trust as well as through missed events.
